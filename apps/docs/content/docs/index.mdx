A library for applications that issue **their own** ES256 or RS256 tokens, for
PostgREST and row-level-security backends — Neon's Data API, Supabase,
self-hosted PostgREST — or anything that trusts a JWKS URL.

The library owns the authentication logic. You own the routing, the database,
and email delivery — the database through four functions you write yourself.

## What it is not

An OAuth authorization server, a hosted service, or the owner of your schema.
There are no database adapter packages and there never will be: four generic
table functions *are* the integration point, which is why the library never
needs to own your schema.

## Five steps

### 1. Install

```bash
bun add @auth-ts/core
```

### 2. Generate a signing key

```bash
bun x @auth-ts/cli keygen
```

That prints `JWT_PRIVATE_KEY` and the public key set, then asks whether to keep
them: the key appended to `.env`, the key set written to `public/jwks.json` — a
static file your framework serves at `/jwks.json`. That key is the only secret
the server holds.

### 3. Write the four functions

```ts
import { createAuth } from "@auth-ts/core"

export const auth = createAuth({
  database: {
    /* select, insert, update, delete — see the AuthDatabase reference */
  },
  email: {
    sendCode: async ({ email, code, purpose }) => {
      const [subject, intro] =
        purpose === "emailChange"
          ? ["Verify your new account email address", "Your email address verification code is"]
          : ["Sign in to your account", "Your sign-in code is"]
      await yourEmailProvider.send({
        to: email,
        subject,
        text: `${intro}: ${code}\n\nDo not share this code with anyone. If you didn't request this, you can safely ignore this email.`
      })
    }
  }
})

export type Auth = typeof auth
```

### 4. Mount one route

```ts
// routes/api/auth/$.ts
export const Route = createFileRoute("/api/auth/$")({
  server: {
    handlers: {
      GET: ({ request }) => auth.handler(request),
      POST: ({ request }) => auth.handler(request),
      DELETE: ({ request }) => auth.handler(request)
    }
  }
})
```

### 5. Point your database at it

Neon takes the JWKS URL directly: `https://your.app/jwks.json`. Supabase
third-party auth takes the issuer instead — `https://your.app/api/auth` — and
discovers the keys itself.

No public folder? Import the file and pass it as `jwks: { json }`, and the server
serves it at `/api/auth/jwks` instead; `jwks: { url }` tells discovery where it
lives if it is hosted somewhere else entirely.

## Then, in the browser

```ts
import { createAuthClient } from "@auth-ts/core/client"

export const authClient = createAuthClient()

await authClient.sendSignInCode({ email })
await authClient.signInWithCode({ code })

// Your PostgREST client asks for the token on every request.
new NeonPostgrestClient({
  dataApiUrl: DATA_API_URL,
  options: { global: { fetch: fetchWithToken(authClient.getToken) } }
})
```
