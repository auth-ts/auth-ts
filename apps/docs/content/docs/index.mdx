A library for applications that issue **their own** RS256 or ES256 tokens, for
PostgREST and row-level-security backends — Neon's Data API, Supabase,
self-hosted PostgREST — or anything that trusts a JWKS URL.

The library owns the authentication logic. You own the routing, the database,
and email delivery — the database through four functions you write yourself.

## What it is not

An OAuth authorization server, a hosted service, or the owner of your schema.
There are no database adapter packages and there never will be: four generic
table functions *are* the integration point, which is why the library never
needs to own your schema.

## Five steps

### 1. Install

```bash
bun add @auth-ts/server @auth-ts/client
```

### 2. Generate a signing key

```bash
bun x @auth-ts/cli keygen
```

That prints `JWT_PRIVATE_KEY`, `AUTH_SECRET`, and the public key set, then asks
whether to keep them: the two variables appended to `.env`, the key set written
to `public/jwks.json` — a static file your framework serves at `/jwks.json`. The two values must differ: one signs tokens, the other keys the
verification-code HMAC, and they have different blast radiuses.

### 3. Write the four functions

```ts
import { createAuthServer } from "@auth-ts/server"

export const authServer = createAuthServer({
  db: {
    /* select, insert, update, delete — see the AuthDB reference */
  },
  email: {
    sendCode: async ({ email, code }) => {
      await yourEmailProvider.send({ to: email, subject: "Your code", text: code })
    }
  }
})

export type AuthServer = typeof authServer
```

### 4. Mount one route

```ts
// routes/api/auth/$.ts
export const Route = createFileRoute("/api/auth/$")({
  server: {
    handlers: {
      GET: ({ request }) => authServer.handler(request),
      POST: ({ request }) => authServer.handler(request),
      PATCH: ({ request }) => authServer.handler(request),
      DELETE: ({ request }) => authServer.handler(request)
    }
  }
})
```

### 5. Point your database at it

Neon takes the JWKS URL directly: `https://your.app/jwks.json`. Supabase
third-party auth takes the issuer instead — `https://your.app/api/auth` — and
discovers the keys itself.

No public folder? Import the file and pass it as `jwks: { json }`, and the server
serves it at `/api/auth/jwks` instead; `jwks: { url }` tells discovery where it
lives if it is hosted somewhere else entirely.

## Then, in the browser

```ts
import { createAuthClient } from "@auth-ts/client"

export const authClient = createAuthClient()

await authClient.sendCode({ email })
await authClient.verifyCode({ email, code })

// Hand this to your PostgREST client as its access token.
const token = await authClient.getToken()
```
