---
title: Token claims
description: What's in the JWT your database reads.
---

```json
{
  "sub": "0199a3c4-7e1b-7c3a-9f2e-4b8d1e6a2c10",
  "sid": "0199a3c4-8f20-7d11-a0b3-5c9e2f7b3d21",
  "role": "authenticated",
  "type": "user",
  "amr": ["otp"],
  "iat": 1771200000,
  "exp": 1771203600
}
```

| claim | value |
| --- | --- |
| `sub` | The user id. |
| `sid` | The session id. Compare it to `sessions.id` to find this device. |
| `role` | The Postgres role your data API switches to. `authenticated` by default. |
| `type` | `guest`, `user` or `admin`. auth.ts writes only the first two. |
| `amr` | How the session signed in, as an array. |
| `iat` | When the token was signed. |
| `exp` | When it expires, `jwt.ttl` after `iat`. |
| `iss` | `<baseURL><basePath>`, only when `baseURL` is set. |
| `aud` | `jwt.audience`, only when it's set. |

The header carries `alg` and `kid`, the key's thumbprint in `jwks.json`.

## How they signed in

| `amr` | sign-in |
| --- | --- |
| `otp` | email code |
| `sms` | text message code |
| `fed` | GitHub or Google |
| `anonymous` | guest |

`otp` and `sms` come from the RFC 8176 registry. `fed` and `anonymous` are the
names large providers use where the registry has none.

## Admins

Make someone an admin in SQL. No endpoint can change `type`:

```sql
update "users" set "type" = 'admin' where "email" = 'you@example.com';
```

Their next token carries `"type": "admin"`.

## Adding claims

See [Custom claims and fields](/docs/guides/claims-and-fields). Anything in a
token is readable by whoever holds it, so keep secrets out.
