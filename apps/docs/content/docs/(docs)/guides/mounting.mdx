---
title: Mounting the handler
description: Serve every auth endpoint from one route.
---

`auth.handler` takes a `Request` and returns a `Response`. Mount it once as a
catch-all for `GET`, `POST` and `DELETE` under `/api/auth`.

```ts tab="TanStack Start" title="src/routes/api/auth/$.ts"
import { createFileRoute } from "@tanstack/react-router"
import { auth } from "~/lib/auth"

export const Route = createFileRoute("/api/auth/$")({
  server: {
    handlers: {
      ANY: ({ request }) => auth.handler(request)
    }
  }
})
```

```ts tab="Next.js" title="app/api/auth/[...all]/route.ts"
import { auth } from "@/lib/auth"

export const GET = auth.handler
export const POST = auth.handler
export const DELETE = auth.handler
```

```ts tab="SolidStart" title="src/routes/api/auth/[...auth].ts"
import type { APIEvent } from "@solidjs/start/server"
import { auth } from "~/lib/auth"

const handler = ({ request }: APIEvent) => auth.handler(request)

export { handler as DELETE, handler as GET, handler as POST }
```

```ts tab="Hono" title="src/index.ts"
import { Hono } from "hono"
import { auth } from "./lib/auth"

const app = new Hono()

app.on(["GET", "POST", "DELETE"], "/api/auth/*", (c) => auth.handler(c.req.raw))

export default app
```

Any other framework that hands your route a web `Request` works the same way.

## A different path

Set `basePath` on the server and the client to the same value:

```ts
createAuth({ basePath: "/auth" /* ... */ })
createAuthClient({ basePath: "/auth" })
```

OAuth callback URLs follow it, so update them in your provider settings too.

## Serving `jwks.json`

`keygen` writes `public/jwks.json`, which most frameworks serve at
`/jwks.json`. If yours has no public folder, pass the key set to the server and
it serves it at `/api/auth/jwks`:

```ts
import jwks from "./jwks.json"

createAuth({ jwks: { json: jwks } /* ... */ })
```

If the file is hosted somewhere else, pass its address as `jwks: { url }`.

## Calling endpoints from the server

Every endpoint is also a function on `auth`, with the same name as the client
method. Server code calls it directly, without an HTTP request to itself. See
[Server-side rendering](/docs/guides/server-side-rendering).
